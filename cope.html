Content and channels

Create Once, Publish Everywhere

Create content once in a structured form, then publish it to every channel without rewriting it.

Daniel Jacobson, NPR, 2009

  1. Write content once, stored in parts: title, summary, body, image, facts.

    Each recipe is stored once: name, time, ingredients, steps, photo.

  2. Each channel takes the parts it needs, automatically.

    Website, retailer apps, pack QR codes and the newsletter.

  3. A change in the source updates every channel.

    A new ingredient updates the recipe everywhere the same day.

The question it answers

Are we rewriting the same content for every channel?

When to use it

  • Content appears in many channels and drifts out of date.
  • Teams rewrite the same content repeatedly.
  • Choosing or rebuilding a content system.

When to skip it

  • Small teams with one or two channels.

How to run it

  1. List content types and the channels that use them.
  2. Define each type as structured fields.
  3. Set up the system so channels pull fields automatically.
  4. Keep editing in one place only.

Common mistakes

  • Content stored as one big block of text.
  • Channels with their own copies that drift.
  • Forcing every channel to look the same.
