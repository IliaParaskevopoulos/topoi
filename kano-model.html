Customer understanding

Kano Model

Not every feature affects satisfaction the same way. Some are expected, some scale with effort, and some delight.

Noriaki Kano and colleagues, 1984

  1. Left to right: how fully a need is met. Bottom to top: how customers feel, from dissatisfied to delighted. The dashed line is neutral.

    Lumora is deciding what to build into the next version of its rapid test reader for GP clinics.

  2. More is better and less is worse, in a straight line. Customers ask for these directly and compare competitors on them.

    Time to result. Every minute saved during a consultation counts.

  3. Expected as standard. Missing them causes strong dissatisfaction, but doing them well never delights. Customers rarely mention them.

    Certified accuracy and the regulatory mark. Without them, no clinic buys.

  4. Delighters customers did not ask for. Missing them does no harm; having them creates real enthusiasm and a reason to choose you.

    Results go straight into the clinic’s patient record, with no typing.

  5. Features customers do not care about either way. They cost money and add little.

    A choice of device colours.

  6. Over time, attractive features become performance features and then must-be features, as competitors copy them and customers get used to them.

    Automatic transfer to the patient record will soon be expected, so Lumora plans its next delighter now.

The question it answers

Which features must we get right, which should we keep improving, and which will make customers choose us?

When to use it

  • Choosing what goes into the next release when budget is limited.
  • Deciding which features to lead with in messaging, and which simply need to be confirmed.
  • Checking whether a planned feature is worth building at all.

When to skip it

  • Very early concepts that customers cannot picture well enough to judge.
  • Deciding price. The model sorts features; it does not tell you what they are worth.

How to run it

  1. List the features you want to test, each described in plain words.
  2. For each feature, ask two questions: how would you feel if it were there, and how would you feel if it were not?
  3. Offer five answers to each: I like it, I expect it, I am neutral, I can live with it, I dislike it.
  4. Use the Kano evaluation table to classify each answer pair, then take the most common category per feature.
  5. Make sure every must-be is covered, invest in the performance features that matter most, and add one or two attractive features.

A fifth category, reverse features, covers things some customers actively dislike. It is left out of the diagram for clarity.

Common mistakes

  • Asking customers what they want instead of the paired questions. They rarely name must-bes or delighters.
  • Treating the result as permanent. Categories shift as the market matures.
  • Leading marketing with must-be features. They prevent losing deals, but rarely win them.
