Pricing and packaging

Value Metric

Choose the unit you charge for so that price grows with the value the customer gets.

Common software pricing practice; no single author

  1. Name the unit you charge for: users, transactions, assets, locations, usage.

    Per maintained machine.

  2. The unit should rise as the customer gets more value.

    More machines kept running means more value.

  3. Buyers must be able to forecast their bill easily.

    Plants know how many machines they have.

  4. Check that the unit does not stop people using the product more.

    Unlike per-user pricing, adding technicians costs nothing.

The question it answers

What should we charge per, so customers pay more only when they get more?

When to use it

  • Launching a new product or pricing model.
  • Customers complain the price does not match the value.
  • Growth in usage is not turning into revenue.

When to skip it

  • One-off purchases where a single price works fine.

How to run it

  1. List candidate units.
  2. Score each on value alignment, predictability and fairness.
  3. Test the top two with customers.
  4. Model revenue for typical customers under each.

Worked example: Tessera

Tessera is a fictional SaaS company whose software helps mid-size manufacturers plan and track equipment maintenance.

Common mistakes

  • Per-user pricing that discourages adoption.
  • Units customers cannot predict.
  • Changing the unit often, which erodes trust.
